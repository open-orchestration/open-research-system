# Findings — Tooling Landscape

**Question:** What does this category teach for building an AI research system?

## Key claims (cited)
- The 2026 framework field splits by primary concern: LangChain+LangGraph (largest ecosystem, graph multi-agent, LangSmith), LlamaIndex (RAG-first, workflow multi-agent), CrewAI (role-based, non-dev friendly), AutoGen (GroupChat, Microsoft camp), PydanticAI (type-safe, handoffs), Mastra (TypeScript standard), DSPy (compiler paradigm), plus vendor SDKs (OpenAI Agents, Vercel AI) — choosing one is choosing a multi-agent model and observability stack — [AI Agent Frameworks 2026 Deep Dive — LangChain, LangGraph, LlamaIndex, CrewAI, AutoGen, PydanticAI, Mastra, DSPy, MCP Complete Guide](https://www.youngju.dev/blog/culture/2026-05-16-ai-agent-frameworks-langchain-langgraph-llamaindex-crewai-autogen-pydanticai-mastra-dspy-mcp-2026-deep-dive.en)
- LangGraph is the orchestration backbone for agentic apps where LangChain's linear "plug-and-play" chains fall short: it gives persistent, stateful workflows with graph-structured logic (loops, branches, conditionals), parallelism (sectioning/voting/worker orchestration), routing, evaluator-optimizer loops, and deployment features (streaming, human approval) — [Choosing Your Agent Toolkit: LangChain, LangGraph, LlamaIndex & AutoGen Explained](https://medium.com/@rtamirasa/choosing-your-agent-toolkit-langchain-langgraph-llamaindex-autogen-explained-c3b2e144a015)
- MCP (Model Context Protocol) support is now universal across frameworks, so the framework choice depends on existing stack rather than MCP availability; MCP standardizes tool access over SSE, Streamable HTTP, and stdio transports, with OAuth 2.0 for authenticated servers — [MCP and AI Frameworks: How LangChain, LangGraph, CrewAI, LlamaIndex, and 10+ Frameworks Integrate the Model Context Protocol](https://chatforest.com/guides/mcp-ai-frameworks-langchain-langgraph-crewai/)
- For RAG/data-pipeline workloads, LlamaIndex is the recommended choice and can expose its workflows *as* MCP servers (`workflow_as_mcp`), giving a bidirectional integration story; the `llama-index-tools-mcp` client (v0.4.8, Feb 2026) consumes remote MCP tools for any LlamaIndex agent — [MCP and AI Frameworks](https://chatforest.com/guides/mcp-ai-frameworks-langchain-langgraph-crewai/)
- DSPy inverts prompt engineering: you declare signatures and modules (e.g. `dspy.ChainOfThought("context, question -> answer")`) and a compiler (MIPROv2, BootstrapFinetune) auto-tunes few-shot selection, instructions, and CoT shape against training data — "prompt engineering gets replaced by code generation," adopted in academia and research labs — [AI Agent Frameworks 2026 Deep Dive](https://www.youngju.dev/blog/culture/2026-05-16-ai-agent-frameworks-langchain-langgraph-llamaindex-crewai-autogen-pydanticai-mastra-dspy-mcp-2026-deep-dive.en)
- PydanticAI ("FastAPI-feel for AI agents") applies Pydantic validation to tool signatures and output schemas, auto-deriving JSON Schema from `@agent.tool` functions and injecting dependencies via `RunContext`, with first-class observability through Logfire/OpenTelemetry — the fastest-growing type-safe LangChain alternative in enterprise — [AI Agent Frameworks 2026 Deep Dive](https://www.youngju.dev/blog/culture/2026-05-16-ai-agent-frameworks-langchain-langgraph-llamaindex-crewai-autogen-pydanticai-mastra-dspy-mcp-2026-deep-dive.en)
- Three cost controls are standard in 2026 production: prompt caching (Anthropic `cache_control` / OpenAI / Gemini, 5-min TTL, cuts cost 75%+ by caching system prompts and tool defs), batch APIs (50% discount for time-insensitive work), and model cascades (try Haiku/Mini, escalate failures to Opus/4 via `with_fallbacks` or PydanticAI `models`); trace-level cost aggregation (LangSmith/Helicone/OpenLLMetry) should be adopted before building a custom dashboard — [AI Agent Frameworks 2026 Deep Dive](https://www.youngju.dev/blog/culture/2026-05-16-ai-agent-frameworks-langchain-langgraph-llamaindex-crewai-autogen-pydanticai-mastra-dspy-mcp-2026-deep-dive.en)
- The space is also surveyed academically: a 2025 arXiv survey catalogs agentic-AI framework architectures, protocols, and design challenges, signaling the field is consolidating around shared patterns rather than one-off designs — [Agentic AI Frameworks: Architectures, Protocols, and Design Challenges](https://arxiv.org/abs/2508.10146)

## Convergent vs contested
- **Convergent:** MCP is the universal tool-integration standard; structured/typed output (Pydantic/Zod) is table stakes; pick one trace-level observability tool early; cost controls (caching, batch, cascades) are standard. LangGraph is the consensus for stateful multi-agent orchestration; LlamaIndex for RAG.
- **Contested / open:** Whether to hand-write prompts (LangGraph/PydanticAI) or compile them (DSPy) is a genuine paradigm split. No framework dominates — choice is driven by language (Python vs TS), team skill (CrewAI for non-devs), and existing stack, not by a clear technical winner.

## Implications for the system (Phase 2)
- Default to LangGraph for the orchestrator/subagent topology (topic 07) — its stateful graph, parallelism, routing, and evaluator-optimizer loops match the required architecture — and LlamaIndex for the RAG/graph retrieval layer (topics 06/09), exposed via MCP.
- Standardize all tool access on MCP (SSE/HTTP/stdio + OAuth) so retrieval, search, and corpus tools are swappable and reusable.
- Enforce typed structured output (Pydantic) on every machine-consumed step, and adopt one trace-level cost/observability tool (LangSmith or OpenLLMetry) before custom dashboards.
- Bake in cost controls from the start — prompt caching for system prompts/tool defs, batch APIs for non-urgent work, model cascades (cheap-first, escalate-on-failure) — since the multi-agent design is 15x token cost (topic 07).
- Evaluate DSPy for the highest-value, repeatedly-run prompts where compiler optimization against a training set beats hand-tuning.
